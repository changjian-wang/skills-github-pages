理解 DeepSeek 的演进，不能只看模型名字和参数规模。更有价值的问题是：每一阶段究竟解决了什么瓶颈？哪些变化发生在网络结构中，哪些来自训练方法和工程系统？

本文的主线是：**用稀疏计算扩大模型容量，用注意力压缩降低缓存开销，再通过训练与系统优化提高效率，并通过后训练增强推理能力。**

> 阅读范围：本文是一篇基础回顾，聚焦 2024 年 1 月至 2025 年 1 月公开技术报告中的 DeepSeek LLM、DeepSeekMoE、DeepSeek-V2、DeepSeek-V3 和初版 DeepSeek-R1。它不是截至文章发布日期的完整版本清单，也不覆盖所有后续更新及多模态分支。

## 一、先看演进路线

下表使用技术报告的首次公开月份，不将论文日期与模型首次发布日期混为一谈。

| 报告时间 | 代表工作 | 核心变化 | 主要关注的问题 |
| --- | --- | --- | --- |
| 2024-01 | DeepSeek LLM | 7B、67B 模型与规模扩展研究 | 怎样分配模型、数据和计算预算 |
| 2024-01 | DeepSeekMoE | 细粒度专家与共享专家 | 怎样让专家分工更灵活、减少知识冗余 |
| 2024-05 | DeepSeek-V2 | 将 MLA 与 DeepSeekMoE 结合 | 怎样兼顾模型容量、计算量和 KV 缓存 |
| 2024-12 | DeepSeek-V3 | 改进负载均衡、MTP、FP8 与 DualPipe | 怎样高效、稳定地训练更大的 MoE 模型 |
| 2025-01 | DeepSeek-R1 | 基于 V3-Base 的多阶段后训练 | 怎样增强复杂任务中的推理能力 |

这里不是一条单纯的结构替换路线：V2、V3 的重点包括网络结构与训练系统，R1 的重点则是如何训练已有的基础模型。

## 二、DeepSeek LLM：从稠密模型理解扩展规律

早期 DeepSeek LLM 研究了 7B 和 67B 两个规模的模型，以及模型规模、数据量和计算预算之间的关系。其 Chat 版本还使用了监督微调与直接偏好优化。相关背景见 [DeepSeek LLM 技术报告][deepseek-llm]。

可以把稠密模型理解为：处理不同 token 时，前馈网络使用同一套固定的计算结构，不会按输入动态选择不同的专家子网络。这里的 token 是模型处理文本的基本单位，并不一定对应一个汉字或一个完整单词。

稠密结构比较直接，但扩大网络通常也会增加计算和存储成本。由此产生一个问题：

**能否保留较大的参数容量，却不让每个 token 都经过全部专家的计算？**

这正是混合专家模型要解决的问题之一。

## 三、DeepSeekMoE：把容量与单次计算部分分开

MoE 是 Mixture of Experts，即混合专家。在这类结构中，部分前馈网络被多个专家子网络替代，由路由器为每个 token 选择其中一部分参与计算。

这里的“专家”是神经网络模块，不是多个聊天机器人，也不是人为指定的“数学助手”“代码助手”。专家如何分工，主要通过训练形成。

[DeepSeekMoE 原论文][deepseek-moe] 强调了两个设计。

### 1. 细粒度专家

将较大的专家拆成更多、更小的专家，在相近的计算预算下允许更多组合。这样，路由器不必只在少数大型专家之间做选择，可以更灵活地组合不同子网络。

目标是提高专家的专门化程度，而不是简单地把专家数量堆高。

### 2. 共享专家

让一部分专家始终参与计算，用来承载不同输入共同需要的知识；其他路由专家则按需参与。

这种设计希望减少路由专家重复学习通用知识的情况，为更有区分度的分工留出空间。但它不意味着每个专家都会对应一个清晰、固定的人类知识领域。

### 总参数不等于激活参数

阅读 MoE 模型介绍时，需要区分：

- **总参数量**：整个模型所包含的参数规模。
- **每 token 激活参数量**：处理一个 token 时参与计算的参数规模，包括相应的公共部分和选中的专家。
- **实际部署开销**：还受权重存储、缓存、通信、精度和推理框架影响。

因此，“只激活少量参数”不等于“只需要存储这些参数”，也不意味着它的延迟必然等同于相同激活规模的稠密模型。专家分布在不同设备上时，还会带来数据通信和负载均衡问题。

## 四、DeepSeek-V2：MoE 降计算，MLA 降缓存

根据 [DeepSeek-V2 官方说明][deepseek-v2]，V2 将 DeepSeekMoE 与 MLA 结合。两者优化的不是同一件事。

### MoE 优化前馈网络的计算分配

MoE 让模型拥有较大的总参数容量，同时只为每个 token 激活部分专家。它主要改变前馈网络的组织方式。

### MLA 优化注意力缓存

自回归模型逐个生成 token 时，通常会缓存历史 token 的 Key 和 Value，避免每一步重复计算已有的表示。这部分缓存称为 **KV Cache**。

上下文越长、并发请求越多，KV Cache 的存储开销往往越大。

MLA 的全称是 Multi-head Latent Attention，即多头潜在注意力。其关键思路是通过低秩联合压缩，用较小的潜在向量表示 Key 和 Value 所需的信息，并结合单独的位置编码部分参与注意力计算。

在论文描述的优化推理方式中，需要缓存的是压缩表示及相应的位置编码部分，而不是为每个注意力头完整保存传统形式的 Key 和 Value。

需要注意三个边界：

- MLA 不是把模型权重做一次普通文件压缩，而是注意力结构本身的设计。
- MLA 减少 KV 缓存，但不等于不再需要缓存。
- 降低缓存占用不等于消除了长上下文注意力的全部计算成本，实际收益还取决于实现。

可以用一句话记住 V2：**DeepSeekMoE 决定哪些专家参与计算，MLA 改变注意力信息怎样表示和缓存。**

## 五、DeepSeek-V3：结构、训练目标与系统协同优化

V3 延续了 MLA 与 DeepSeekMoE，而不是抛弃 V2 重新设计整个模型。它进一步改进了专家负载均衡、训练目标和分布式训练系统，详见 [DeepSeek-V3 技术报告][deepseek-v3]。

### 1. 负载均衡：避免少数专家过忙

如果大量 token 都选择同一批专家，会出现一些设备很忙、另一些设备空闲的情况。传统做法常通过额外的负载均衡损失约束路由，但约束过强也可能影响模型原本要优化的任务。

V3 的主要策略是为专家引入用于路由选择的偏置，根据训练批次中的实际负载动态调整：过载专家的偏置降低，负载不足专家的偏置提高。

一个容易误读的细节是：**“辅助损失自由”的负载均衡策略，不表示整个训练过程完全没有辅助损失。** V3 仍保留了权重很小的序列级均衡损失，用于防止单条序列内出现极端不均衡。

### 2. MTP：让训练关注不止下一个 token

MTP 是 Multi-Token Prediction，即多 token 预测。V3 在通常的下一个 token 预测之外，增加对更后续 token 的预测目标，以提供更丰富的训练信号。

它的实现保留预测之间的因果关系，不是让几个互不关联的输出头随意预测未来文本。V3 报告中的配置使用一层额外 MTP 模块，在通常的下一 token 目标之外，再预测一个后续 token。

训练和推理阶段也需要分开理解：

- 训练时，MTP 是增强主模型的额外目标。
- 推理时，可以不使用 MTP 模块，由主模型正常自回归生成。
- 也可以将 MTP 模块用于推测解码，但需要相应的候选验证流程和推理实现，不能理解为无条件一次输出多个正确 token。

### 3. FP8：降低部分计算与存储开销

V3 使用 FP8 混合精度训练，让大量计算密集型操作使用较低精度，同时对数值敏感的部分保留更高精度。

“混合精度”是关键：它不是把所有权重、梯度、累加和优化器状态都强制变成 8 位。低精度带来的效率提升，需要与缩放方式、累加精度和数值稳定性配合。

### 4. DualPipe：减少设备等待

MoE 的专家并行涉及跨设备通信。DualPipe 通过流水线调度，让部分计算与通信重叠，减少流水线空闲时间。

这说明架构效率不能只从参数表判断。同样的网络结构，配合不同的通信实现、并行方式和硬件拓扑，实际训练效率可能明显不同。

### 参数规模对照

下表采用官方报告中的主体模型口径，B 表示十亿个参数。

| 模型 | 总参数量 | 每 token 激活参数量 | 结构关系 |
| --- | --- | --- | --- |
| DeepSeek-V2 | 236B | 21B | MLA 与 DeepSeekMoE 的结合 |
| DeepSeek-V3 | 671B | 37B | 延续上述结构并改进路由及训练 |
| 初版 DeepSeek-R1 | 671B | 37B | 基于 DeepSeek-V3-Base 后训练 |

V3 的 671B 是主体模型的参数口径；其官方仓库还说明，额外 MTP 模块权重约为 14B。因此，不能把下载权重总规模与主体模型规模混为一谈。参数量也不能直接换算成服务速度。

## 六、DeepSeek-R1：重点是后训练，不是另一套骨干网络

[DeepSeek-R1 官方说明][deepseek-r1-repo] 明确指出，初版 R1-Zero 和 R1 都基于 DeepSeek-V3-Base。也就是说，它们继承了 V3 的主体结构，但采用不同的后训练路线。

### R1-Zero：直接在预训练模型上进行强化学习

R1-Zero 探索不先做监督微调，直接对已有基础模型开展大规模强化学习。这里的“直接”很重要：**它不是跳过预训练，也不是从随机参数开始只靠奖励学会语言。**

论文报告了这种训练下出现的检查、反思和更长推理过程，同时也指出了可读性较差、语言混用等问题。

### R1：加入冷启动与多阶段训练

为了增强推理能力并改善输出可读性，[R1 技术报告][deepseek-r1] 描述了以下流程：

1. 使用少量高质量冷启动数据，对 V3-Base 进行监督微调。
2. 开展面向推理任务的强化学习。
3. 从强化学习检查点生成并筛选样本，结合非推理数据，再对 V3-Base 进行监督微调。
4. 进行覆盖更多场景的强化学习，兼顾推理能力、有用性和安全性。

第三步不是简单地在上一阶段权重上继续堆叠训练：论文明确描述了利用筛选后的数据重新微调 V3-Base。

### GRPO 是训练算法，不是注意力机制

GRPO 的全称是 Group Relative Policy Optimization。它对同一个问题采样一组回答，利用组内奖励的相对关系估计优势，从而更新模型；不需要像某些 PPO 实现那样额外训练一个独立的价值模型。

这不等于训练不需要奖励信号。答案如何评分、哪些任务能够可靠验证，仍然直接影响训练效果。GRPO 改变的是训练方法，不是用来替换 MLA 或 MoE 的网络层。

### 蒸馏版也不等于缩小的 R1 网络

初版 R1 发布的蒸馏模型以 Qwen、Llama 系列中的稠密模型为基础，通过 R1 产生并整理的数据进行微调。

所以，使用 R1-Distill 模型不意味着它也具有完整 R1 的 MLA 与 MoE 结构。**蒸馏是在传递能力，不是按比例复制教师模型的每一个模块，也不是普通的权重量化。**

## 七、把几个概念放回正确的位置

| 概念 | 所属层面 | 应当如何理解 |
| --- | --- | --- |
| DeepSeekMoE | 网络结构 | 用专家路由组织前馈计算 |
| MLA | 网络结构 | 用潜在表示减少注意力 KV 缓存 |
| MTP | 训练目标与附加模块 | 提供额外预测信号，也可支持推测解码 |
| FP8、DualPipe | 数值计算与训练系统 | 优化精度、存储、通信和设备利用率 |
| SFT、RL、GRPO | 后训练方法 | 通过示例和奖励改变模型行为 |
| R1-Distill | 能力迁移方法 | 用教师生成的数据训练较小模型 |

从这些基础节点可以看到，DeepSeek 的进展不是单靠“参数更多”或某一个独立技巧获得的。网络结构、数据、训练目标、后训练和工程系统共同影响最终能力与成本。

阅读后续模型时，可以继续问四个问题：

1. 它改变了什么：网络结构、训练数据、优化目标，还是部署方式？
2. 它减少的是什么：计算量、缓存、通信，还是训练样本需求？
3. 它增加了什么代价：实现复杂度、权重存储、输出长度，还是验证成本？
4. 它的结论在什么模型版本、硬件、任务和评估设置下成立？

比起记住一串版本号，能回答这些问题，更有助于真正理解大模型的架构演进。
